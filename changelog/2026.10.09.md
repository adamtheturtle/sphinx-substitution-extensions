# 2026.10.09 (2026-10-09)

## Changes

- Support MyST substitutions defined in document frontmatter.
  ([#1554](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1554))
- Preserve Sphinx's tracking of files consumed by the `include` directive.
  ([#1632](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1632))
- Restore Sphinx's source-directory-relative handling of slash-prefixed `include` paths.
  ([#1633](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1633))
- Restore Sphinx's `include-read` event for the `include` directive and compose listener changes with content substitutions, including for parsed and literal include content, while preserving nested includes' substitution settings.
  ([#1634](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1634))
- Avoid shared mutable defaults in the substitution code role.
  ([#1717](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1717))
- Validate equivalence-case TOML values without untyped pass-through helpers.
  ([#1718](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1718))
- Type MyST parsing contexts as docutils and MyST context classes instead of arbitrary objects.
  ([#1722](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1722))
- Type substitution option collections by the names they contain.
  ([#1723](https://github.com/adamtheturtle/sphinx-substitution-extensions/issues/1723))
- Publish native Markdown release notes and use the same notes in documentation where available.
- Use a backported recursive type alias to enable runtime type checking of nested substitution flattening while retaining Python 3.11 support.
  Require Beartype 0.23.0rc2 and typing-extensions 4.6.0 or newer.
